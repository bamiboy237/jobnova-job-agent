Jobnova Codebase Map & Architecture

Technical reference for navigating, extending, and testing the autonomous career agent.

1 · System Overview

Jobnova is an autonomous career search and applicant tracking system (ATS) application product. It unifies two operations into one runtime:

  1. Job Source Resolution: Resolves raw LinkedIn job URLs to direct employer or external ATS application links (such as Lever, Greenhouse, or Workday).
  2. Guarded Application Automation: Guides candidate interactions through real-time chat, inspects application forms, completes fields with candidate facts, prompts privately for unknown values, and halts for explicit human approval before submitting.

The system runs as a single-process Node 22 server. It couples a Mastra agent runtime to Playwright browser automation (local Chrome or remote Browserbase instances), serving both backend REST/SSE APIs and a statically compiled Next.js single-page application.

2 · Architecture & Boundary Separation

Jobnova separates intent reasoning from browser mutations and candidate data storage. The model never receives direct access to the DOM or candidate personal data: 

┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Client Presentation Layer (web/)                                         │
│    Next.js SPA · Vercel AI SDK useChat · JobnovaTransport (SSE translation) │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. HTTP Server & Session State (src/server.ts, src/server/runStore.ts)       │
│    Single Node 22 process · Access gate · RunStore SQLite persistence       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. Agent Coordination Runtime (src/career/careerAgent.ts)                   │
│    Mastra unified thread loop · Tool dispatches · Compaction middleware     │
├──────────────────────────────────────┬──────────────────────────────────────┤
│ 4. LinkedIn Resolver (src/resolver/) │ 5. Guarded Apply Engine (src/apply/) │
│    - Deterministic DOM extraction   │    - pageInspection (@ref handles)   │
│    - Stagehand AI fallback           │    - execute_application_actions     │
│    - validateDestination() checking  │    - candidateCatalog (memory bind)  │
├──────────────────────────────────────┴──────────────────────────────────────┤
│ 6. Browser Session Management (src/browser/)                                │
│    CDP connectivity · Browserbase remote · Local Chrome debugging           │
└─────────────────────────────────────────────────────────────────────────────┘

Key architectural separation:

  • Value-Free Representation: When inspecting form fields, pageInspection.ts maps DOM inputs to synthetic ref tokens (like @first or @email). The model plans actions using these tokens and semantic keys.
  • Guarded Execution: Real values are bound in memory within pure TypeScript functions (candidateCatalog.ts). Form inputs are written to the browser without reflecting raw values back to model conversation history.
  • One-Click Submission: Autonomous submission retry is prohibited. The engine captures a pre-submission screenshot and suspends execution until the user manually confirms.

3 · System Entry Points

The codebase provides four execution entry points:

File Type Description
src/server.ts Production HTTP Server Starts the unified server on PORT (default 3000). Serves API endpoints (/api/runs, /api/chat), Server-Sent Events, static Next.js assets from web/out/, and handles Railway health probes.
src/index.ts CLI Resolver Direct command-line tool. Invoked via npm run resolve -- <linkedin-url>. Resolves a single LinkedIn URL and prints structured JSON output to stdout.
src/apply/chatCli.ts CLI Career Agent Interactive terminal client. Invoked via npm run apply:chat. Launches a full conversational loop in the terminal supporting live tool feedback and user prompting.
src/auth.ts Authentication Utility Invoked via npm run auth. Launches a browser session to log in to LinkedIn interactively, saving session cookies for persistent local or Browserbase contexts.

5 · End-to-End Execution Pipelines

Pipeline A: Resolving a LinkedIn Job Posting

  1. Submission: User submits a LinkedIn job URL via web UI or CLI (src/index.ts).
  2. Deterministic DOM Extraction: directResolver.ts navigates to the page and inspects the DOM for direct external apply links. If found, it extracts the target URL immediately (zero LLM tokens used).
  3. AI Fallback: If the link is obscured or multi-step, Stagehand observes page elements and clicks through redirects.
  4. Invariant Validation: validateDestination.ts verifies that the resolved URL is HTTPS, external to LinkedIn, and points to a known ATS or valid careers page.
  5. Persistence: The resolved destination and execution metrics persist to SQLite (RunStore).

Pipeline B: Multi-Turn Career Guidance & ATS Application

  1. Message Ingestion: User message streams into POST /api/chat/:id/message.
  2. Context Compaction: compactSupersededSnapshots deletes stale DOM snapshots from earlier turns in prepareStep.
  3. Form Control Discovery: pageInspection.ts scans the active ATS page, assigning synthetic @ref identifiers.
  4. Batch Execution: Agent invokes execute_application_actions with up to 20 operations (filling facts, selecting options). Actions run sequentially in pure TypeScript.
  5. Interactive Suspension: If private candidate data is missing, the agent calls request_user_inputs. The turn pauses; client displays a single consolidated form card.
  6. Pre-Submission Audit: The agent captures a full-page screenshot.
  7. Human Confirmation: Execution pauses. The user reviews the screenshot and clicks Confirm submission. Only then does the engine execute the single final click.

6 · Architectural & Safety Invariants

Enforce these four invariants across all contributions:

InvariantEnforcement LocationRule
Candidate Data Isolation src/apply/generalBrowserTools.ts Model prompts receive only structural references (@ref) and semantic fact keys. Real values are bound in memory within TypeScript and never returned in tool responses.
One-Click Submission src/apply/generalBrowserTools.ts Automated retry of final submission is prohibited. The engine must conduct a pre-submission DOM audit, save a full-page screenshot, and require explicit human authorization.
Strict Destination Validation src/resolver/validateDestination.ts Candidate URLs must use HTTPS and point outside LinkedIn. Reject login walls, registration prompts, and generic search listings.
Browser Concurrency Ceiling src/server.ts & src/career/careerSession.ts Maintain at most two concurrent live browser sessions. Enforce a 10-minute idle release timer to release remote browser resources.
